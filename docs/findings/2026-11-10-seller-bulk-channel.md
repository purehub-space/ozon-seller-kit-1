# 店铺页批量取库存通道（已验证）

> 建立时间：2026-11-10 20:40 CST
> 结论状态：**已实测打通**，一次请求 41 对库存 / 38 个独立 SKU

## 一、为什么值得做

| 通道 | 1 次请求带回 | 1 万件的请求数 |
|---|---|---|
| PDP API `url=/product/{sku}/` | 1 个 SKU | 10,000 |
| **店铺页 `url=/seller/{slug}/products/`** | **38–41 个 SKU** | **约 430** |

**约 24–40 倍请求效率提升。**

## 二、店铺 URL 用 slug，不用数字 ID

- 店铺页真实 slug 示例：数字 ID `4616499` → slug **`jinghongtu`**
- 两种都能请求成功，但 slug 是站内主用法（分页请求里只用 slug）

### seller_name → slug 推断规则（实测 4/5 命中）

规则：**转小写 → 空格换连字符 → 去掉特殊字符（«»、点、引号等）**

| seller_name | 推断 slug | 实测结果 |
|---|---|---|
| Сима-Ленд - Маркет | `sima-lend` | ✓ 200，标题「Каталог Сима-Ленд」 |
| NNN SHOP | `nnn-shop` | ✓ 200，标题「Каталог NNN Shop」 |
| СИМБАТ | `simbat` | ✓ 200，标题「Каталог СИМБАТ」 |
| ФОРМИКС | `formiks` | ✓ 200，标题「Каталог ФОРМИКС」 |
| Малыши и Малышки | `malyshi-i-malyshki` | ✗ 200 但 134KB，标题为空 |

**判据：响应 ≥200KB 且标题含「Каталог」= slug 正确；<150KB 或标题空 = 未命中。**

`seller_name` 存在于 `ozon-seller-kit/data/toys-slim.db` 的 `sku` 表，29,823 行全覆盖。

## 三、请求方式

```
GET https://www.ozon.ru/api/entrypoint-api.bx/page/json/v2?url=/seller/{slug}/products/
```

- 需街道地址态（`Москва, Тверская улица, 1`），否则库存字段缺失
- `url=` 必须用未编码的完整路径串；用 `params={"url":...}` 会把 `/` 编码、落到别的页面
- 浏览器页内 fetch 需 `credentials:'include'` + `headers:{'x-o3-app-name':'dweb_client'}`
- 首页 referer 即可，无需先渲染店铺页

## 四、★ 解析陷阱（两次踩坑，务必记住）

响应里的商品 JSON 是**二次编码**：

```
\"quantityButton\":{\"maxItems\":2000, \"updateCartAction\":{\"id\":\"1546517660\", ...
```

- ❌ 直接正则 `"quantityButton":\{"maxItems"` → 0 命中（误判「API 不含库存」）
- ❌ `html.unescape()` → 仍然 0 命中（`\"` 不是 HTML 实体）
- ✅ **`t.replace('\\"','"')` 后再正则** → 41 对

而**渲染后 DOM** 里是 HTML 实体 `&quot;` 编码：

```
&quot;quantityButton&quot;:{&quot;maxItems&quot;:2000, ...
```

- ✅ 对 DOM 用 `html.unescape()` → 46 对

两种来源要分别处理，别用同一套正则。

解析正则（自己实测）：
```python
p = re.findall(r'"quantityButton":\{"maxItems":(\d+),\s*"updateCartAction":\{"id":"(\d+)"', t.replace('\\"','"'))
```

## 八、产能结论

**476 个头部卖家 × 1 请求 = 11,540 个 SKU**，约 4 分钟（2 请求/秒），配合会话配额 150 提前熔断 → 需 4 个会话（每次 mint 约 70 秒）。

混合策略（全量 29,823）：
1. 头部 476 卖家 → 店铺页批量（11,540 个，约 15 分钟含 mint）
2. 剩余 18,283 个长尾 → PDP + 每 150 请求自动 mint（约 3.5 小时）

前 1 万件用店铺批量可压到约 15 分钟。

### 搜索接口反查 slug 也无效

`url=/search/?text={urlencode(店名)}&from_global=true` → 返回 142–157KB，**`/seller/` 链接 0 个**。搜索页不暴露店铺 slug。

### 因此实际覆盖

- 476 个卖家 × 25% 命中 ≈ **119 个可用店铺**
- 119 × 38 = **约 4,522 个 SKU（15% 的 29,823）**
- 只需 119 请求，约 1 分钟

**结论修正：店铺通道是「头部加速器」，不是主力。** 剩下 85% 仍必须走 PDP。

## 十、★ 关键修正：API 返回的是推荐位，不是店铺商品

用池内头部卖家 `sima-lend`（在 `toys-slim` 里有 345 个 SKU）复测，结论逆转：

| 对比项 | 结果 |
|---|---|
| sima-lend 店铺页返回 SKU 与目标池交集 | **0** |
| sima-lend 返回 SKU 与 jinghongtu 返回 SKU 交集 | **10/38** |
| jinghongtu 返回 SKU 与目标池交集 | **0** |

**说明 `/seller/{slug}/products/` 的 `page/json/v2` 响应带回来的 38 个 SKU 是「通用推荐位商品」，不是该店铺的商品。** 虽然页面标题正确显示「Каталог Сима-Ленд」，但商品流不是它的。

真实店铺商品在**渲染后的 DOM** 里，且两套商品不同：

| 来源 | SKU 数 | 与另一来源交集 |
|---|---|---|
| 渲染后 DOM | 38 | 10 |
| API JSON | 38 | 10 |

**所以纯 HTTP 拿不到店铺商品，必须渲染页面（goto + 等待 + 解析 DOM）。**

## 十一、一个店铺页能拿到哪些字段（渲染 DOM 实测）

以 jinghongtu 店铺页（38 个商品）为例：

| 字段 | 有值数 | 覆盖率 | 可信度 |
|---|---|---|---|
| **库存** `maxItems` | **38/38** | **100%** | 高，但 23 个 2000 封顶 |
| 价格 `PRICE`/`ORIGINAL_PRICE` | 23/38 | 61% | 高 |
| 折扣 `discount` | 39 处 | — | 高 |
| 评分 `"text":"4.9"` | 23/38 | 61% | 高 |
| **评论数** `"N отзывов"` | **17/38** | **45%** | **低**，部分数值是品牌级汇总（见下） |
| **销量变化** | **0/38** | **0%** | **完全没有** |

### 评论数不可直接采信

DOM 里出现的评论数横跨四个数量级：`49`、`3`、`90`、`2 209`、`44 780`、`142 192`、`264 317`、`1 524 115`。

`1 524 115 отзывов` 对一个玩具 SKU 不可能成立，是**品牌或店铺级汇总**。而 17/38 的商品根本没有评论数字段。

**结论：店铺页的「N отзывов」不能当作单 SKU 评论数使用。**

### 销量变化完全没有

DOM 内 `sold` 仅 3 处（非销量语义）、`продано`/`заказов`/`куплен` **0 处**。

**店铺页拿不到任何销量或销量变化字段。** 销量只能从 PDP 或列表页的 `sold_count` 拿（`toys-slim.db.sku` 里那列是一次性快照，非实时）。

## 十二、字段能力总结

| 通道 | 库存 | 价格 | 评分 | 评论数 | 销量变化 | 成本 |
|---|---|---|---|---|---|---|
| PDP API `url=/product/{sku}/` | ✅ 真值 | ✅ | ✅ | ✅ | ✅ `sold_count` | 1 请求/1 SKU |
| 店铺页渲染 DOM | ✅ 38 个 | ✅ | ✅ | ⚠️ 混杂 | ❌ | 1 渲染/38 SKU，10–15 秒 |
| 店铺 API JSON | ❌ 是推荐位 | ✅ | ✅ | ⚠️ | ❌ | 1 请求但拿不到店铺商品 |
| 类目页 HTML | ✅ 9.5 个/页 | ✅ | ✅ | ❌ | ❌ | 1 请求/9.5 SKU |

**所以「库存 + 评论 + 销量变化」三件套里，店铺页只能解决库存和价格；评论数不可信、销量完全没有。** 要全套字段必须回到 PDP。
